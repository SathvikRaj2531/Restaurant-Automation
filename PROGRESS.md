# PROGRESS - P Cube Charcoal Food Den

Stack: Node 22 + Express + built-in SQLite (`node:sqlite`), vanilla JS front end. Run: `cd /app && npm start` (seeds, then serves on PORT 3000).

## Modules done
- **A1 Foundation** - data models (settings, dining_tables, menu_categories, menu_items, visits, orders + order_items, waiter_requests, bills, payments, users, sessions), re-runnable seed (6 tables, 4 role users, 63 menu items), token auth with scrypt-hashed passwords, Change Password API and screen (`/staff/change-password`), staff login (`/staff/login`), public menu API (`GET /api/menu`).

- **A2 Public website** - Home, Menu, About, Contact (server-rendered, `server/views.js`), shared menu component (`public/js/menu-ui.js`) with search, category tabs, veg/non-veg filter, unavailable greying; per-page title and meta description, one H1 per page, LocalBusiness JSON-LD, `/robots.txt`, `/sitemap.xml`, custom 404, placeholder favicon. Placeholder image blocks only.

- **A3 Customer QR ordering** - `/t/{qr_token}` page (unknown token -> "Table not found", "Table N" on every screen), menu with search/tabs/veg filter, portion picker, quantity stepper, per-dish notes, cart drawer with order note and grand total, confirm step, duplicate-tap guard (client lock + server idempotency key), live "My orders" status (4 s polling). Server validates token and items, recalculates all prices from the menu (client prices ignored), stores name/portion/price snapshots, reuses the table's open visit or auto-creates one, creates the order as `new` with an order number (format `DDMM-NNN`, India time). Customers cannot cancel. `/staff/qr` (owner/manager) shows every table's permanent QR with a Print button.

- **A4 Staff orders, acceptance, kitchen display** - `/staff` (owner/manager) with tabs Live, Tables, History; Live shows new orders first with a strong highlight, then in-progress; Accept, Reject (reason required), Cancel (staff only, reason required, any status except completed/cancelled), Mark Served; waiting time, item notes, overall note; "Enable sound" button, beep on new orders, tab title shows pending count. Tables tab: grid coloured free / new order / in progress with open-visit order count, running total and a placeholder waiter-request badge. History: completed and cancelled orders filtered by date (India time) and table. `/kitchen` (kitchen role; owner may also view): accepted-and-later orders, oldest first, large cards, Start Preparing and Mark Ready, over-10-minute highlight (`KITCHEN_WAIT_WARN_MINUTES` in `server/settings.js`), same sound option, no prices, no cancel/accept. All role checks are enforced in the API (`server/routes/staff.js`, `server/routes/kitchen.js`); status changes are atomic, so double taps return a 409 and cannot skip steps. Polling every 4 s. Smoke test: 25 API checks (flow, permissions, history/table filters, pages load) passed.

- **B1 Call Waiter** - Customer page: floating "Call Waiter" button -> "Do you want to call the waiter to your table?" Yes/No. Request statuses `requested -> acknowledged -> completed`, shown live to the customer (4 s polling; "completed" stays visible for `WAITER_COMPLETED_VISIBLE_SECONDS`). Duplicates are blocked on the server (partial unique index: one active request per table), so a second tap or a second phone just shows the existing request. `/waiter` (waiter role only): open requests with table number and waiting time, Acknowledge and Complete, sound option, 4 s polling. Manager/owner `/staff`: the Tables-grid badge now shows the open-request count, a request list with Acknowledge/Complete sits above the grid, and the Tables tab shows a count. The old unused `waiter_requests` table (open/resolved) is migrated automatically on start. Smoke test: 19 checks passed.
- **B2 Menu management** - `/staff/menu` (owner/manager; "Menu" button on `/staff`): items listed by category with search, quick Available and Special toggles, add/edit item (name, description, category, subcategory, veg/non-veg, portions with label and price, image URL, special, available), soft delete (`deleted_at`), category add/rename/reorder (up/down). Empty price = "Price to be confirmed" (not orderable). The public and QR menus refetch every 30 s and on tab focus (quietly; the QR cart drops items that became unavailable and says so); `GET /api/menu` is `no-store`. The order API rejects an unavailable item with a message naming it. Stored orders keep their own name/price snapshots, so edits never change them (tested). Seed fix: the menu seed now only runs on an empty menu, so a restart can never bring back renamed or deleted seed items. Smoke test: 32 checks passed.
- **B3 Billing and payments** - Owner `/staff/settings`: restaurant name, address, phone, GSTIN, tax percent, service charge percent (empty = none, 0 is saved as none; nothing assumed). Table detail `/staff/table/N` (Tables-grid cards link to it; manager/owner): the open visit, all non-cancelled orders combined by item and portion, running total labelled "not a bill". Record Payment (Cash / UPI / Card, optional reference for UPI/Card) with a confirm step: in one transaction the server creates the immutable bill `PC-000001`, `PC-000002`, ..., stores one payment, closes the visit and sets the visit's orders to `completed`. Bills store aggregated lines, tax and service lines only if configured, final total, method, paid status and a snapshot of the restaurant header, so reprints never change; database triggers reject any UPDATE/DELETE on bills and payments. `/staff/bill/PC-xxxxxx` (only reachable after payment): "Bill (Print)" uses an 80 mm thermal layout (`@page size: 80mm auto`) via the browser print dialog, "Download PDF" returns a one-page 80 mm PDF made without a library (Courier; shows "Rs." because the built-in PDF font has no rupee glyph); reprints are unlimited. `/staff/bills`: bill history with search by bill number, table and date. After payment the next order automatically opens a new visit and gets a new bill. Waiter and kitchen get 403 on every billing route. Guards: payment is refused while a `new` (unaccepted) order exists; if orders are accepted/preparing/ready the screen asks for confirmation before taking payment anyway. Smoke test: 31 checks passed.

- **B4 Analytics and final polish** - `/staff/analytics` (owner/manager; "Analytics" button on `/staff`): filters Today, Yesterday, Last 7 days, Last 30 days, Custom range (India-time day boundaries, max one year). Uses ONLY paid bills, so cancelled orders are never counted. Shows revenue, paid bills, total orders (non-cancelled orders in paid visits), average order value (revenue / paid bills), a daily revenue chart, monthly revenue (calendar months inside the selected range), best-selling and least-selling items (top 10 each by quantity, only items with at least one sale, portions merged per item), peak hours (orders by India-time hour), and table performance (revenue and bill count per table, all tables listed). Charts are dependency-free SVG in the brand colour, with hover/focus tooltips and a "View as table" fallback. Waiter and kitchen get 403. Polish: loading and error states on every screen (with Try again where it helps); a browser pass over all staff, public and QR screens at phone width found no JavaScript errors (the only console line is the browser noting the intentional 404 status on the custom 404 page); `README.md` lists roles, how temporary logins work, environment variables, and every placeholder; no secrets in code. Smoke test: 18 analytics checks passed.

- **C1 Visual redesign and SEO (requested after B4)** - New charcoal-and-ember theme (still all in `theme.css`; saffron accent, Playfair Display + Inter via Google Fonts). Public Home, Menu, About, Contact and 404 redesigned: full-width hero with the grill artwork, category tiles, "order in three steps", hours/location, gallery, FAQ, footer. Every placeholder image is now original vector artwork in `public/img/art/*.svg` (hero, kababs veg/non-veg, soup, starters veg/non-veg, noodles, grill, ambience, generic), and every menu item shows a thumbnail: its own `image_url` if set in `/staff/menu`, otherwise the artwork for its category (`defaultArt()` in `server/data.js`). These are illustrations, not photographs: no real food photography could be sourced here. To use real photos, upload them anywhere public and paste the link in the item's Image URL field. SEO: unique titles and descriptions within length limits, one H1 per page, canonical + hreflang en-IN, Open Graph and Twitter cards (`/img/og-card.jpg`), JSON-LD (Restaurant with opening hours and cuisine, WebSite, FAQPage on Home; Menu/MenuSection/MenuItem with INR prices on Menu; BreadcrumbList on Contact; placeholders are never put in structured data), the menu is server-rendered so crawlers see every dish without JavaScript, sitemap with lastmod, robots.txt, `/llms.txt` (plain-language facts for AI assistants), web manifest, favicon and PNG icons, 30-day caching for images, `fetchpriority` on the hero. Verified: 63 thumbnails load on `/menu` and on the QR ordering page, ordering still works, no JavaScript errors.
- C1 notes: the artwork files contain fixed colours (SVGs cannot read CSS variables), like the favicon. Hours are published in structured data as every day, because only one set of hours is stored; change `restaurantJsonLd()` in `server/views.js` if days differ. Google Fonts are loaded from Google; self-host them if you need zero third-party requests.

## Known issues / notes
- Colours live only in `public/css/theme.css`. Exception: `public/favicon.svg` (SVG favicons cannot read CSS variables).
- Restaurant details are stored as `[ADD ...]` placeholders in the `settings` table (see the placeholder list in README.md).
- Temporary passwords are random, printed once by the seed, and each user is forced to change it at first login.
- Tax rule (a decision, not a business fact): service charge = percent of subtotal; tax = percent of (subtotal + service charge); each rounded to whole rupees. Change `totals()` in `server/billing.js` if the accountant wants a different base.
- Payment is full payment by one method; split payments are not supported.
- The restaurant settings editor covers only name, address, phone, GSTIN, tax and service charge. Tagline, about text, maps link, reviews source and social links are still edited directly in the `settings` table.
- Manager and kitchen temporary passwords were regenerated on 2026-11-12 because the earlier ones were not recorded. The owner had already changed theirs and was left alone.
- Analytics assigns each bill to the India-time day it was paid (`paid_at`), so a bill paid just after midnight counts for the next day.
- Not tested by automation: printing on a real 80 mm thermal printer (the layout uses `@page { size: 80mm auto }`; please do one test print and check margins) and the sound alerts (browsers need one tap on "Enable sound" per page load).
- Analytics "monthly revenue" covers the months inside the selected filter, not a fixed 12-month history. Say so if you want a fixed view instead.
- Skipped / failed items: none.
